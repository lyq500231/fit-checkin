# 健身打卡 FitCheck

一个**纯前端、零依赖、完全离线**的健身打卡单页应用。
双击 `index.html` 即可在浏览器中使用，所有数据保存在浏览器 `localStorage`，不上传任何服务器。

## 快速开始

1. 用 Chrome / Edge 等现代浏览器打开 `index.html`（无需安装、无需联网）。
2. 打开「计划」页，按自己的分化安排每周训练模板（也有一键载入的模板：推/拉/腿、全身 3 天、居家无器械）。
3. 回到「打卡」页：每天会自动带入当天计划，点「+ 添加一组」记录次数与重量，系统自动判定 **达标 / 超额 / 未达标**。
4. 想看统计效果可以先在「设置 → 载入示例数据」生成 80 天模拟数据体验。

## 功能一览

### 打卡
- 日期前后切换 / 日历选择 / 快捷键 `←` `→` `T`
- 每个动作记录多组「次数 × 重量」，自动判定：
  - **达标** = 次数 ≥ 目标下限 且 重量 ≥ 目标重量
  - **超额** = 超过目标上限或目标重量
  - 自重 / 计时类动作（目标重量为 0 或目标为「60秒」）只校验次数
- 「⚡ 补满」按目标值一次填满剩余组；「📋 复制上次」把最近一次同名训练的组数与重量带过来，方便渐进超负荷
- 组间休息计时器（完成一组自动弹出，可 ±15 秒，结束有提示音 + 振动）
- 自动统计当日达标组数、完成动作数、总容量、训练时长
- 训练感受（5 档表情）+ 当日小结
- 「🧘 标记休息日」：主动休息不会打断连续打卡

### 统计
- 连续打卡天数（顶部火焰）、最长连续
- 本周 / 本月达标天数与完成率、累计训练天数、累计容量、累计时长
- 月度日历热力图（按完成度着色，含容量数字，点击日期跳转打卡）
- 近 12 周趋势柱状图（训练容量 / 达标天数 / 训练时长 三种口径）
- 单动作进步曲线（最大重量 / 最佳次数 / 动作总容量 / 完成组数）
- 个人最佳 PR 表（最大重量、对应次数、最佳次数、单组最大容量、累计容量）
- 12 枚成就徽章

### 计划
- 周一到周日 7 天模板，可改主题、切换休息日、增删改动作、调整顺序
- 每个动作：目标组数、次数区间（如 `8-12`，也支持 `60秒`/`25分钟`）、目标重量、组间休息
- 修改计划不影响已保存的历史记录

### 身体数据
- 体重 / 体脂率 / 腰围 / 胸围 / 臀围 / 臂围 / 腿围 + 备注
- 每个指标迷你趋势图与涨跌提示，点击卡片看大图与最高/最低/总变化
- 历史记录表，可逐条删除

### 数据与备份
- 导出 JSON 备份 / 导入（支持「合并」与「覆盖」）
- 导出训练明细 CSV、身体数据 CSV（带 BOM，Excel 打开中文不乱码）
- 清空全部数据
- ⚠️ 数据只在本机浏览器里，**清浏览器数据或换设备前请先导出 JSON**

## 设置项
昵称、重量单位（kg/lb）、每周起始日、每周目标达标天数、默认组间休息、
达标线（完成度 ≥ 30%~100% 记为当天达标，默认 60%）、自动休息计时、提示音开关。

## 快捷键
| 键 | 作用 |
|---|---|
| `←` / `→` | 打卡页切换前/后一天 |
| `T` | 回到今天 |
| `1`-`5` | 切换 打卡/统计/计划/身体/设置 |
| `Esc` | 关闭弹窗 / 结束休息计时 |

## 常见问题
- **换电脑/换浏览器记录没了？** 数据在 localStorage，请用「设置 → 导出 JSON 备份」迁移，再在新设备「导入」。
- **想多人/多设备同步？** 目前定位是单机本地工具；可用网盘同步导出的 JSON 文件手动合并。
- **次数填什么？** 计时/距离类动作把目标写成 `60秒`、`25分钟`、`5km` 等，次数栏填实际完成量即可。
## 多人 / 多设备使用

本应用是**纯前端**的：每个人打开后数据存在**自己浏览器**里，互不干扰，也不需要服务器。
想让别人也能用，按需求选一条路线：

### 路线 A：同一 Wi-Fi 内共享（0 成本，立刻可用）
```powershell
powershell -ExecutionPolicy Bypass -File .\serve.ps1
```
脚本会打印 `http://<本机IP>:8000/`，同一 Wi-Fi 下的手机/同事浏览器打开即可。
每人各自的记录存在各自设备里。换端口：`-Port 9000`。

### 路线 B：公网网址（推荐，免费）
把本文件夹（除 `_test` 外）上传到任一静态托管，即得到一个全网可访问的网址：
- **GitHub Pages**：新建仓库 → 上传文件 → Settings → Pages → 部署 main 分支根目录
- **Cloudflare Pages / Netlify / Vercel**：直接把文件夹拖进网页即可
部署后手机浏览器打开网址 → 菜单里「添加到主屏幕 / 安装应用」，就变成了一个**离线可用的 App（PWA）**，
带独立图标（`icons/`）、全屏运行、断网也能用（Service Worker 缓存）。

### 路线 C：微信小程序 / 应用商店 App
- 小程序：需要注册小程序主体 + 服务器域名 ICP 备案 + 审核，成本最高；且本项目的数据模型是本地存储，
  改造为小程序需要重写存储层（云开发可替代）。
- 商店 App：可用 Capacitor/Tauri 把本网页套壳打包 APK/EXE，本质还是路线 B 的网页。
一般个人/小团队使用，**路线 B 的 PWA 已经等于一个 App**，不建议先做小程序。

### 路线 D：多人共用一份数据（教练看学员、家庭共享）
当前版本每人数据独立。若需要"一个账号多人同步/汇总"，需要加后端：
- 最省事：Supabase / LeanCloud 免费额度（auth + 表），我可以把存储层改成云端同步；
- 或自建：一台轻量云服务器 + SQLite + 本目录静态文件。
需要的话告诉我选哪个，我来改。

### 数据迁移提醒
换设备/换浏览器时：设置 → 导出 JSON 备份 → 新设备导入（可选合并/覆盖）。
